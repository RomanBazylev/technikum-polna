# Technikum Polna: Фундамент

- Дата: 2026-08-26
- Статус: согласовано
- Область: подсистема «Фундамент». Остальные пять подсистем получат собственные спецификации.
- Репозиторий: https://github.com/RomanBazylev/technikum-polna
- Адрес: https://romanbazylev.github.io/technikum-polna/

## Контекст

Приложение для учеников Technikum Kinematograficzno-Komputerowe im. Krzysztofa Kieślowskiego, ul. Polna 7, Варшава, специальность technik programista. Статический сайт на GitHub Pages, без бэкенда, двуязычный польско-русский.

Первичный пользователь — ученик первого класса 2026/2027, носитель русского языка. Приложение публичное, им может пользоваться любой ученик школы.

Исследование, на котором основан дизайн, лежит в плане проекта. Ключевые установленные факты: квалификации INF.03 и INF.04, экзамены после 3 и 4 класса по версии школы, электронный дневник Librus, устав школы с точной шкалой оценок и порогами посещаемости, действующий рамочный план Dz.U. 2026 poz. 1028 załącznik nr 5, набор 2026 года не попадает под реформу образования и доучивается по нынешней программе.

## Декомпозиция проекта

Проект разрезан на шесть подсистем. Эта спецификация описывает первую.

| Подсистема | Содержание | Очередь |
|---|---|---|
| Фундамент | Оболочка, схемы, состояние, CI, деплой | 1 |
| П1 Справочник | Правила школы, права иностранца, деньги и дорога, первая неделя, глоссарий, сроки | 2 |
| П2 Калькуляторы | Бюджет пропусков, «какая оценка нужна», шкала § 52, законность контрольной | 3 |
| П3 Карта программы | Ось efektów, предметы, темы, лектуры, каталог ресурсов | 4 |
| П4 Мастерская | Песочницы SQL и PHP, предпросмотр разметки, обработка изображений | 5 |
| П5 Сообщество | Приём материалов от других учеников | отложено |

Порядок определяется затуханием пользы. Справочник ценен в первые недели учёбы и дешевеет по мере адаптации. Мастерская нужна к практическому экзамену INF.03 в июне 2029 года и до третьего класса не востребована.

## Что входит в Фундамент

- Проект Astro со строгим TypeScript, настроенный на подпуть `/technikum-polna/`.
- Коллекции контента со схемами zod и политикой двуязычности на уровне коллекции.
- Единое хранилище пользовательского состояния `AppState` с версией, экспортом и импортом.
- Компонент двуязычного термина с озвучкой.
- Движок датированных обязанностей с четырьмя типами якорей.
- Оболочка: нижняя навигация из четырёх вкладок, тёмная тема, мобильная вёрстка.
- Клиентский поиск Pagefind.
- PWA с областью действия под подпутём.
- CI: проверка типов, валидатор контента, сборка, деплой через GitHub Actions.
- Дымовые тесты Playwright по живому адресу.

## Что не входит

- Содержательные тексты справочника. Фундамент везёт по одному образцовому документу на коллекцию.
- Калькуляторы, карта программы, песочницы.
- Любая интеграция с Librus. Обоснование в разделе «Отвергнутые решения».
- Аккаунты, сервер, аналитика, реклама.

## Архитектура

Два разных момента времени, и это основа всей конструкции.

**Сборка на серверах GitHub.** Astro компилирует markdown в статические страницы, забирает внешние данные, строит индекс поиска. Все обращения к чужим API происходят здесь, поэтому нет ни CORS, ни зависимости от доступности чужого сервера в момент визита.

**Визит в браузере ученика.** Отдаются готовые файлы. Расчёты выполняются на устройстве. Введённые данные лежат в localStorage и никуда не отправляются, потому что отправлять некуда. Отсутствие слежки — свойство конструкции, а не обещание.

Тяжёлый WebAssembly для будущей Мастерской грузится с jsDelivr, а не с Pages, и в предзагрузку сервис-воркера не попадает никогда.

### Обоснование выбора Astro

Встроенные content collections со схемами zod дают валидацию контента без нашего кода, а страницы отдаются без JavaScript. Альтернатива в виде Vite с React потребовала бы собственного слоя загрузки и валидации контента.

### Редактор кода

CodeMirror 6, не Monaco. Решает мобильность: Monaco на телефоне практически неработоспособен. Относится к будущей Мастерской, зафиксировано здесь, чтобы не переигрывать позже.

### Ограничения площадки

GitHub Pages не позволяет задавать свои HTTP-заголовки, поэтому недоступны `COOP`, `COEP` и `SharedArrayBuffer`. Выбранный стек в них не нуждается. Проектировать решения, которым они нужны, запрещено.

Проектный сайт живёт на подпути, из чего следует обязательное указание `site` и `base` в конфигурации Astro и ограничение области действия сервис-воркера. Это самая частая причина поломки, которая не видна локально.

## Модель данных

### Общие типы

```ts
type Locale = 'pl' | 'ru';
type Grade = 1 | 2 | 3 | 4 | 5;
type Qualification = 'INF.03' | 'INF.04';

// 'INF.03.3.5', разбирается один раз из извлечения ORE
type EffectCode = string & { readonly __brand: 'EffectCode' };
```

### Происхождение материала

Определяет, можно ли встроить содержимое или только дать ссылку. Список встраиваемых лицензий намеренно не содержит вариантов с `NC`, поэтому смешение CC BY-NC-SA с нашей CC BY-SA на одной странице невозможно технически.

```ts
type EmbeddableLicense = 'public-domain' | 'CC-BY-3.0' | 'CC-BY-SA-4.0' | 'LAL-1.3';

type Source =
  | { kind: 'link-only'; provider: string; title: string; url: string; why: string }
  | { kind: 'embeddable'; title: string; url: string; license: EmbeddableLicense; attribution: string }
  | { kind: 'authored'; author: string; license: 'CC-BY-SA-4.0' };
```

У ссылочного варианта нет поля с содержимым, поэтому скопировать чужой текст нельзя. Поле `why` обязывает автора объяснить причину и превращает юридическое решение в документацию.

### Датированные обязанности

Якоря разные по природе, поэтому объединение, а не одно поле с датой.

```ts
type SchoolEvent = 'rada-klasyfikacyjna' | 'koniec-zajec' | 'poczatek-roku';

type DeadlineAnchor =
  // повторяется каждый учебный год, границы в формате MM-DD
  | { kind: 'annual-window'; from: string; to: string }
  // разовый срок конкретного года, границы в формате YYYY-MM-DD
  | { kind: 'fixed-date'; from: string; to: string }
  | { kind: 'before-event'; event: SchoolEvent; days: number }
  | { kind: 'after-event'; event: 'absence-ended'; days: number };

type Obligation = {
  id: string;
  title: Record<Locale, string>;
  what: Record<Locale, string>;
  anchor: DeadlineAnchor;
  appliesTo: 'wszyscy' | 'cudzoziemcy' | { grade: Grade };
  legalBasis: string;
  handledAt: 'szkola' | 'ops' | 'esdos' | 'librus';
  reviewBy?: string; // дата ISO 8601, YYYY-MM-DD
};
```

Четыре якоря, а не три, потому что повторяющийся ежегодный срок и разовая дата ведут себя по-разному. Stypendium szkolne подаётся с 1 по 15 сентября **каждого** года, это `annual-window`, и движок разворачивает его на текущий учебный год. Сроки адаптаций на матуре привязаны к конкретной сессии, это `fixed-date`. Хранить первое полной датой означало бы ежегодно править контент.

Поле `legalBasis` обязательно и всегда выводится на экран: в разговоре с учителем или в секретариате номер параграфа весит больше пересказа.

### Коллекции контента и политика двуязычности

Двуязычность задаётся схемой коллекции, а не глобальной настройкой.

| Коллекция | Политика языков | Причина |
|---|---|---|
| `handbook` | `pl` и `ru` обязательны оба | Правила, права и деньги должны быть понятны ученику и родителю без словаря |
| `obligations` | `pl` и `ru` обязательны оба | Пропущенный срок стоит денег |
| `glossary` | `pl`, `ru`, необязательно `en` | Суть коллекции |
| `topics` | `pl` обязателен, `ru` только термины | Ученик обязан выучить польский термин, а не заменить его русским |
| `resources` | `pl` обязателен, `ru` необязателен | Названия чужих материалов не переводим |

Файл, нарушающий политику своей коллекции, не собирается.

### Состояние пользователя

Единственный владелец localStorage. Шесть подсистем получают срезы, а не прямой доступ.

```ts
type TopicProgress = 'new' | 'learning' | 'known';

type AppState = {
  version: number;
  profile: { grade: Grade; languageGroup: 'niemiecki' | 'hiszpanski' | null; uiLocale: Locale };
  timetable: TimetableEntry[];
  attendance: AttendanceRecord[];
  grades: GradeRecord[];
  homework: HomeworkItem[];
  progress: Record<string, TopicProgress>;
  teachers: TeacherEntry[];
  settings: { theme: 'system' | 'light' | 'dark'; showRussian: boolean };
};
```

Типы элементов `TimetableEntry`, `AttendanceRecord`, `GradeRecord`, `HomeworkItem` и `TeacherEntry` определяются спецификацией П2 «Калькуляторы», которая ими владеет. Фундамент фиксирует только имена полей верхнего уровня, порядок версионирования и механику экспорта, чтобы срезы не пришлось переименовывать позже.

`teachers` хранится только локально и никогда не попадает в репозиторий. Школа состав преподавателей не публикует, поэтому публикация собранных учениками имён создала бы вопрос по RODO без всякой необходимости.

## Границы, ошибки и устаревание

Валидация живёт только на границах. Внутри системы типам доверяем без повторных проверок.

**Граница контента, время сборки.** Схема, происхождение, лицензия, битые ссылки. Нарушение роняет сборку.

**Граница внешних данных, время сборки.** Ответы чужих API кэшируются в репозиторий как снимок. При недоступности источника сборка использует последний удачный снимок и пишет предупреждение в лог. Недоступность чужого сервиса не имеет права ломать наш выпуск.

**Граница хранилища, время чтения.** Разбор через zod. При несовпадении версии выполняется миграция. При неустранимой ошибке разбора старое значение сохраняется под ключом с меткой времени, и приложение стартует с пустого состояния. Данные ученика не стираются никогда.

**Ошибки в браузере.** Телеметрии нет, сервера нет. Каждый интерактивный остров обёрнут в границу ошибок, чтобы упавший компонент не обнулял страницу.

**Устаревание.** Необязательное поле `reviewBy` на единицах контента. CI не падает, но печатает отчёт по просроченным. Правила практик получают такую дату сразу: это самое подвижное место в законодательстве.

## Тесты

Покрываем то, где тест действительно ловит ошибку.

- Чистые функции с законными порогами: вычисление сроков от четырёх типов якорей, включая разворот ежегодного окна на текущий учебный год и перескок через границу календарного года, отображение процентов в оценку по § 52 устава, пороги посещаемости § 54 и § 58. Такие тесты работают документацией устава: при изменении правил красный тест укажет место.
- Разбор и миграция `AppState`, включая сценарий повреждённых данных.
- Валидатор контента: образцовый документ проходит, намеренно испорченный роняет CI.
- Дымовые тесты Playwright по живому адресу на Pages, а не по localhost. Так ловится поломка подпути, невидимая при локальной разработке.

Разметку Astro юнит-тестами не покрываем.

## Критерии готовности

Фундамент готов, когда выполняются все семь утверждений. Каждое проверяемо и каждое можно опровергнуть.

1. Живой адрес отдаёт страницу, стили и изображения разрешаются под подпутём.
2. По одному образцовому документу в каждой коллекции проходит схему, намеренно испорченный документ роняет CI.
3. Компонент термина показывает польский, по нажатию открывает русский и произносит польский голосом.
4. `AppState` переживает перезагрузку, выгружается в JSON и загружается обратно; повреждённые данные откатываются в резервный ключ без потери.
5. Движок обязанностей на зафиксированной дате возвращает ожидаемый список: 5 сентября показывает stypendium szkolne как открытое, 20 сентября как просроченное, а якорь `after-event` считается от даты события, а не от сегодня.
6. Playwright зелёный по живому адресу на Pages.
7. Первая загрузка меньше 300 килобайт, WebAssembly не подгружается.

## Отвергнутые решения

| Решение | Причина отказа |
|---|---|
| Собственный банк из 2000 экзаменационных вопросов | Существует минимум четыре живых открытых проекта, включая Marmo77/egzamin-programista и Chr1skyy с 125 арками |
| Зеркалирование данных Librus | Открытого API нет, коммерческий стоил бы сотни тысяч злотых в год, компания закрыла Szkolny.eu юридическим требованием в 2020 году, а серверная синхронизация означала бы хранение логинов школьников |
| Пуш-уведомления и обновление чаще раза в три часа | Ровно то платное преимущество, ради защиты которого Librus закрыл Szkolny.eu |
| Оценки и отзывы об учителях | Юридический риск, и это просто некрасиво |
| Публичный справочник учителей в репозитории | Школа состав не публикует, публикация персональных данных создаёт вопрос по RODO. Справочник только локальный |
| ИИ-репетитор и собственная теория по непроверяемым предметам | Выдуманные факты при реальной цене ошибки. Своя теория и задачи только там, где правильность проверяется запуском кода |
| Ссылки на odrabiamy.pl, brainly.pl, gotowiec.pl, skul.pl | Готовые ответы к тем же учебникам Nowa Era и Stentor, сомнительное происхождение прав, платный доступ, и существуют они, чтобы списать |
| Реклама и спонсорство | Лицензия CC BY-NC-SA у Pi-stacja и Khan Academy считает рекламу коммерческим использованием и закрыла бы доступ к лучшим бесплатным видео |
| Чат и форум | Модерация переписки несовершеннолетних — ответственность, которую проект не потянет |
| Синхронизация между устройствами через сервер | Сервера нет по замыслу. Только ручной экспорт и импорт файла |

## Принципы оформления

Приложение должно быть явно на стороне ученика, а не родителя. Формулировки строятся как союзник: «можешь пропустить ещё 11 часов», а не «ты пропустил 12 часов». Ничего похожего на отчётность родителю. То, что данные не покидают устройство, написано видимым текстом, а не спрятано в политике конфиденциальности.

Польский термин всегда присутствует, русский перевод рядом или по нажатию. Ученик должен выучить слово `sprawdzian`, а не заменить его словом «контрольная».

## Открытые вопросы

- Лицензия репозитория. Пакет `mysql-on-sqlite` распространяется под GPL-2.0 или новее, и его встраивание сделает соответствующую часть GPL. Решается при спецификации Мастерской, когда станет ясно, выносится ли песочница в отдельный пакет.
- Точная сессия экзамена INF.04. Школа пишет «po 4 klasie», типовая практика по стране — зимняя сессия пятого класса. Разница в семь месяцев меняет запас времени перед матурой. Уточнить у руководителя практического обучения.
- Школьный план часов и веса оценок не опубликованы, достаются из Librus после начала занятий.
- В каких двух классах школа поставит edukacja zdrowotna. Решение директора, вариантов три.
- Часы работы секретариата расходятся: на сайте 9:00–14:00, в BIP 8:00–15:00.
- Правила использования телефонов изменятся: школа обязана переписать устав до 31 декабря 2026.
